# Agri Design — SIH Requirement Probing, /grill-me & PRD Generation

## Purpose

Turn a hackathon idea into a sharp SIH-ready product definition, pitch story, judging strategy and complete PRD.

## `/grill-me` mode

Ask tough questions before implementation.

### Problem fit

- What exact problem statement are we solving?
- Is the user farmer, extension worker, official, FPO, input dealer or enterprise?
- What is the crop, geography and season?
- What pain happens today and why existing systems fail?

### Solution truth test

- What works today in the prototype?
- What is simulated?
- What is future roadmap?
- What will judges see live?
- What can fail during demo?

### Impact test

- What loss are we reducing?
- What cost are we reducing?
- What evidence supports the claim?
- Who benefits besides the farmer?

### Feasibility test

- What data sources are free and reliable?
- What requires government integration?
- What requires field validation?
- What is the cost per farmer or device?

## PRD template

```text
# Product Requirements Document

## 1. Problem Statement
## 2. Target Users
## 3. Current Pain Points
## 4. Proposed Solution
## 5. User Journey
## 6. Core Features
## 7. Non-Functional Requirements
## 8. Data Sources
## 9. AI/ML Scope
## 10. Offline Strategy
## 11. Safety and Trust
## 12. Success Metrics
## 13. Demo Flow
## 14. Roadmap
```

## SIH slide guidance

A 6-slide deck usually works well:

1. Title and problem statement
2. Proposed solution
3. Technical approach
4. Feasibility and viability
5. Impact and benefits
6. Research and references

## Farmer-story framework

Use this emotional arc:

```text
Loss → Confusion → Early Warning → Clear Action → Saved Crop → Shared Learning
```

## Output standards

- Write in simple language.
- Use tables for evaluator comparison.
- Include exact demo claims.
- Add “what is next” without pretending it is already built.
